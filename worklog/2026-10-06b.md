### 2. Section 8 — Full replacement: JWT Design, Session Management, and Revocation
- **8.0** Three mechanisms documented as distinct: `JWT exp`, `auth_version`, `sessionId`/revocation
- **8.1** JWT payloads updated: added `sessionId` and `iat` to both facility user and super admin tokens
- **8.2** `sessions` table schema added — replaces `refresh_tokens` table reference; single source of truth for session state + refresh tokens
- **8.3** Redis revocation state defined: `revoked_session:`, `user_revoked_since:`, `facility_revoked_since:` key patterns
- **8.4** Redis unavailability — fail-closed pattern for BOTH session revocation and auth_version checks: Redis → DB fallback → 503 if both fail. Same pattern for both checks.
- **8.5** Revocation functions: `revokeSession()`, `revokeAllUserSessions()`, `revokeAllFacilitySessions()` — 3-step pattern (DB → Redis → audit log). Automatic trigger table included.
- **8.6** Refresh token revocation: bound to session, refresh exchange checks `revoked_at IS NULL`
- **8.7** Long-running job cancellation: BullMQ jobs store `_meta.sessionId/userId/facilityId/iat`, check at batch checkpoints via `isSessionOrUserRevoked()`
- **8.8** Auth version (existing) — renumbered, added explicit fail-closed Redis fallback
