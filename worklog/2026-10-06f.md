## Key Design Decisions Captured in Tasks

### Refresh Token Format (T019)
Refresh token rotation creates a **new session row** rather than updating in place. This enables clean theft detection: if an old (rotated) token is presented, `sessions.revokedReason='rotated'` is detected → all user sessions revoked → `REFRESH_TOKEN_REUSE` 401.

The expired access token is sent alongside the refresh cookie to extract `sessionId` — JWT is parsed with `{ ignoreExpiration: true }` to get the claim without verifying expiry.

### Cross-Pharmacy Account Linking (T012)
- Email globally unique in `users` table
- If email exists + facilityUsers link exists for this facility → `EMAIL_IN_USE`
- If email exists + no link for this facility → argon2.verify current password → if match: create new facilityUsers row (same userId); if mismatch → `ACCOUNT_EXISTS_LOGIN`
- If email not found → create new user

### Session Creation via superAdminDb (T015)
Sessions are inserted via `superAdminDb` directly (through auth-queries.service helpers), not through `withTenantContext`, because `facilityId` can be null for platform super-admins and `withTenantContext` requires a non-null facilityId.

### authVersion Increment Rules (T024, T028)
- **Single logout** (`POST /auth/logout`): authVersion NOT incremented — only current session revoked via Redis + DB
- **Logout-all** (`POST /auth/logout-all`): authVersion incremented by 1 — all access tokens issued before this point rejected
- **Password reset complete** (`POST /auth/reset-password`): authVersion incremented + all sessions revoked

### Email Service (T003)
`sendMail` wrapped in try/catch. Email failures are logged but do NOT throw — email failure must not block the HTTP response (verification token is already written to DB; user can request resend).
