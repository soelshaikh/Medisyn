## Decisions Made

### CONFIRMED: Facility identification for public endpoints
Public `/api/v1/catalogue/products` and `/api/v1/catalogue/categories` require `X-Facility-ID` header (UUID). A missing/invalid header = 400. Inactive facility = 403. No "browse all facilities" concept.

### CONFIRMED: Product search via ILIKE + pg_trgm GIN index
`ILIKE '%keyword%'` on `name` + `description` columns, with `pg_trgm` GIN indexes. Meets <1s SC-003 target at 10k rows. Full tsvector/relevance ranking deferred.

### CONFIRMED: Category hierarchy via adjacency list + recursive CTE
`parent_id UUID REFERENCES categories(id)`. Tree reads use `WITH RECURSIVE`. Cycle prevention via recursive CTE check before any parent assignment. PostgreSQL 16 supports this cleanly.

### CONFIRMED: Inventory concurrency via SELECT FOR UPDATE
Pessimistic locking within `withTenantContext()` transaction. Single-facility pharmacy: contention on one inventory row is negligible. Atomic `UPDATE inventory_records SET quantity = quantity + $delta ... RETURNING quantity`.

### CONFIRMED: Money as NUMERIC(10, 2)
All price/discount/total columns: `numeric('col', { precision: 10, scale: 2 })`. Returned as strings from postgres.js; compared with Decimal arithmetic in service layer. Never JavaScript floats.

### CONFIRMED: Images as TEXT[] (URL references only)
`text('images').array()`. Upload infrastructure deferred to Phase 9.

### CONFIRMED: Variant model — single dimension, child table
`product_variants` table. Parent `products.variant_dimension_label` (nullable, e.g., "Strength"). Variants have own SKU + price + inventory. Multi-axis variants deferred.

### CONFIRMED: UNIQUE NULLS NOT DISTINCT for inventory_records
PostgreSQL 16+ syntax: `UNIQUE NULLS NOT DISTINCT (product_id, variant_id)`. One row per product (no variants) or one row per variant.

### CONFIRMED: inventory_transactions is append-only
`REVOKE UPDATE, DELETE ON inventory_transactions FROM app_user` — mirrors the `audit_log` pattern from Phase 1.

### CONFIRMED: Coupon codes normalized to UPPERCASE on write
Service layer normalizes before INSERT. Unique constraint on uppercased code per facility.

## New Tables (Phase 3)

All 6 tables are facility-scoped with RLS:

| Table | Key Columns |
|-------|-------------|
| `categories` | `facility_id`, `parent_id` (self-ref), `slug` (unique per facility), `is_active` |
| `products` | `facility_id`, `sku` (unique), `slug` (unique), `category_id`, `price` (numeric), `variant_dimension_label` |
| `product_variants` | `facility_id`, `product_id`, `sku` (unique), `dimension_value`, `price` |
| `inventory_records` | `facility_id`, `product_id`, `variant_id` (nullable), `quantity`, `allow_negative` |
| `inventory_transactions` | `facility_id`, append-only, `quantity_delta`, `resulting_balance`, `reason`, `actor_id` |
| `coupons` | `facility_id`, `code` (unique, uppercase), `type`, `discount_value`, `total_redemption_count` |
