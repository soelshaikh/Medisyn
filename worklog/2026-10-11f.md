## Bugs Found and Fixed

### 1. Wrong API port in all API calls
- **File**: `admin/.env.local`, `admin/src/lib/apiClient.ts`
- **Bug**: `NEXT_PUBLIC_API_URL=http://localhost:4000/api/v1` — backend runs on port 3001
- **Fix**: Changed to `http://localhost:3001/api/v1` in both `.env.local` and apiClient.ts fallback

### 2. `fullName` mismatch in login response handling
- **File**: `admin/src/app/(auth)/login/page.tsx`
- **Bug**: `data.user.fullName` — backend super-admin login returns `{ firstName, lastName }`, no `fullName` field
- **Fix**: `` `${data.user.firstName ?? ''} ${data.user.lastName ?? ''}`.trim() ``

### 3. `InvoiceStatus` union missing "issued" and "void"
- **File**: `admin/src/types/admin.ts`
- **Bug**: `InvoiceStatus = "draft" | "finalized" | "cancelled" | "system_cancelled"` — pages use `inv.status === "issued"` and `inv.status === "void"` which TypeScript flagged as no-overlap comparisons
- **Fix**: Added `"issued" | "void"` to the union

### 4. `AdminInvoice` missing fields used in pages
- **File**: `admin/src/types/admin.ts`
- **Bug**: `voidReason`, `voidedAt`, `customerPhone` referenced in invoice pages but not typed on `AdminInvoice`
- **Fix**: Added all three as optional fields

### 5. `invoicesApi.void()` method missing
- **File**: `admin/src/api/invoices.api.ts`
- **Bug**: `invoices/[id]/page.tsx` called `invoicesApi.void(id, reason)` but method didn't exist in the API module
- **Fix**: Added `void: (id, reason) => apiClient.patch(...)` returning `AdminInvoice`

### 6. `AdhocInvoicePayload` missing `customerPhone`
- **File**: `admin/src/api/invoices.api.ts`
- **Bug**: `invoices/new/page.tsx` included `customerPhone` in the create payload but type interface didn't include it
- **Fix**: Added `customerPhone?: string` to `AdhocInvoicePayload`

### 7. `Pagination` prop name mismatch: `onChange` vs `onPage`
- **Files**: `admin/src/app/(dashboard)/invoices/page.tsx`, `admin/src/app/(dashboard)/inventory/movements/page.tsx`
- **Bug**: Both pages used `onChange={setPage}` but the `Pagination` component interface declares `onPage: (p: number) => void`
- **Fix**: Changed `onChange` → `onPage` in both usages

### 8. `inv.issuedAt` possibly undefined passed to `fmtDate()`
- **File**: `admin/src/app/(dashboard)/invoices/[id]/page.tsx`
- **Bug**: `fmtDate(inv.issuedAt)` where `issuedAt?: string` — TypeScript error: Argument of type `string | undefined` not assignable to `string`
- **Fix**: `inv.issuedAt ? fmtDate(inv.issuedAt) : '—'` in 2 places (PageHeader description and dl Row)

### 9. `(auth)/layout.tsx` missing entirely
- **File**: `admin/src/app/(auth)/layout.tsx`
- **Bug**: Route group `(auth)` had no layout.tsx; without it the login page couldn't resolve as a proper App Router route
- **Fix**: Created minimal layout that renders `{children}`

### 10. `decodeJwt.ts` missing entirely
- **File**: `admin/src/lib/decodeJwt.ts`
- **Bug**: Auth store and route guard import `decodeJwtPayload` and `isTokenExpired` from `@/lib/decodeJwt` but the file didn't exist
- **Fix**: Created with `atob()`-based implementation

## Architecture Notes (Discovered During Audit)

- **Token storage pattern**: Access token lives in `sessionStorage` (key: `access_token`), not in Zustand state. Only `user` + `isAuthenticated` are persisted to `localStorage` via Zustand `persist`. This means same-tab page refresh works (sessionStorage persists across F5), but opening a new tab would require token refresh via the httpOnly cookie.
- **Route group naming**: Tasks spec'd `(protected)` but existing code uses `(dashboard)`. Same pattern, different name — both are valid App Router route group names. Tasks.md updated to reflect actual implementation.
- **Component naming**: Tasks called for `Sidebar.tsx`, `TopHeader.tsx`, `ShellLayout.tsx` — existing code has `AdminSidebar.tsx`, `AdminTopbar.tsx`, shell composition in layout.tsx directly. Functionally equivalent.
- **Login page complexity**: The existing `login/page.tsx` is a full featured component with saved-accounts dropdown (up to 5), remember-me toggle, keyboard navigation, and password visibility toggle — well beyond the spec scope. The API call is inline rather than in a separate `api/auth.ts` module.
