# Session: 2026-10-11n — Admin Facilities Service: Prefix + identityDb Staff Creation

## Context

Task #6: Update `admin-facilities.service.ts` and router to use the enterprise identity architecture. Facility creation now requires a `prefix`. Staff creation writes to identityDb (not vtech-core.users), creates `health_professionals` + `user_roles` in vtech-core. Staff listing queries new enterprise tables with identityDb cross-join. Super admin creation moved to identityDb.

## Files Modified

### `backend/src/core/super-admin/admin-facilities.service.ts`
- **Imports added**: `eq` from drizzle-orm; `identityDb`, `identityUsers` from `@/db`/`@/db/schema/identity`; `getIdentityUserByEmail`, `createIdentityUser`, `resolveUniqueUsername` from identity-queries service
- **`AdminFacilityDetail`**: Added `prefix: string | null` field
- **`FacilityStaffMember`**: Renamed `facilityUserId` → `healthProfessionalId`; changed `roleName: string` → `roles: string[]`
- **`SEAT_ROLE_MAP`**: Updated to enterprise role enum values: `admin_seats → facility_admin`, `staff_seats → staff`, `pharmacist_seats → pharmacist`
- **`adminListFacilities`**: Changed `LEFT JOIN facility_users` count to `LEFT JOIN health_professionals` (active only)
- **`adminGetFacilityById`**: Added `f.prefix` to SELECT; changed user count to `health_professionals` count; added `prefix: r.prefix ?? null` to return
- **`adminCreateFacility`**: Added `prefix: string` param; added prefix uniqueness check (`SELECT COUNT FROM facilities WHERE prefix = X`); `INSERT INTO facilities` now includes `prefix` column; keeps legacy `facility_roles` seed for migration compat (with `ON CONFLICT DO NOTHING`)
- **`adminGetFacilitySeatConfig`**: Usage count query changed from `facility_users JOIN facility_roles` to `health_professionals JOIN user_roles` with `ur.role IN ('facility_admin', 'staff', 'pharmacist')`
- **`adminListFacilityStaff`**: Full rewrite — two-phase approach:
  1. Query vtech-core: `health_professionals JOIN user_roles` for facility, group roles by HP
  2. Batch-fetch user details from identityDb by userId list
  3. Merge and return `FacilityStaffMember[]` with `roles: string[]`
- **`ROLE_NAME_TO_ENUM`**: New map: `admin → facility_admin`, `pharmacist → pharmacist`, `staff → staff`
- **`adminCreateFacilityStaff`**: Full rewrite:
  1. Get facility prefix from vtech-core (503 if not set)
  2. Check email not in identityDb
  3. Generate qualified username `{prefix}{emailLocal}` via `resolveUniqueUsername`
  4. Hash password; create user in identityDb (`accountType='facility_user'`)
  5. In vtech-core transaction: INSERT `health_professionals` + INSERT `user_roles` with `facilityRoleEnum` value
  6. On vtech-core failure: best-effort cleanup of orphaned identity user; throw
  7. Returns `{ id: healthProfessionalId }`
- **`adminListSuperAdmins`**: Rewritten to query identityDb `WHERE accountType = 'super_admin'`
- **`adminCreateSuperAdmin`**: Rewritten to:
  - Check email in identityDb
  - Generate username via `resolveUniqueUsername` (no prefix — super_admin)
  - Create in identityDb with `accountType='super_admin'`, `facilityPrefix=null`
  - Returns `{ id: userId }`
