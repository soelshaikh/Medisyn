### 5. Invoice PDF 401 Fix — `pdfUrl` → `downloadPdf`

**Root cause:** `pdfUrl()` returned a bare URL string. When used as `<a href="...">`, the browser opens it directly with no headers — the backend returns 401 because no Authorization token is sent.

**Fix:** Replaced `pdfUrl()` with `downloadPdf(id, filename?)` in both API files:
```ts
const response = await apiClient.get(`/invoices/my/${id}/pdf`, { responseType: "blob" });
const url = URL.createObjectURL(new Blob([response.data], { type: "application/pdf" }));
const a = document.createElement("a"); a.href = url; a.download = filename; a.click();
URL.revokeObjectURL(url);
```
Uses the authenticated axios instance — Bearer token is sent automatically.

**All call sites updated** (4 files):
- `frontend/src/app/patient/invoices/page.tsx` — per-row `downloadingId` state, spinner on active row
- `frontend/src/app/patient/invoices/[id]/page.tsx` — `downloading` boolean, spinner replaces icon
- `admin/src/app/(dashboard)/invoices/page.tsx` — per-row `downloadingId` in DataGrid column
- `admin/src/app/(dashboard)/invoices/[id]/page.tsx` — `downloading` boolean, Spinner xs

### 6. Invoice PDF 500 Fix — `playwright-core` → `playwright`

**Root cause:** `playwright-core` is a "bring your own browser" package — it has zero bundled binaries. On first PDF request, `chromium.launch()` fails because no Chromium executable is found, causing a 500.

**Fix:**
- `backend/package.json`: `"playwright-core"` → `"playwright"` (full package, manages browser downloads)
- `backend/src/lib/playwrightPdf.service.ts`: dynamic import changed from `"playwright-core"` → `"playwright"`

**Setup required (one-time):**
```
cd backend && npm install
npx playwright install chromium
```

### 7. Invoice Sidebar Not Showing — Permissions Seed

**Root cause:** `invoices.read/create/void` were added to `permissions.catalog.ts` in the previous session, but the DB seed hadn't been re-run. The admin role's permissions array in MongoDB was the old list — `hasPermission("invoices.read")` returned false, hiding the entire Invoices group.

**Fix:** Re-run `npm run seed` — the seed uses `$set` upsert (idempotent), so it safely adds the new permissions and updates the admin role's permissions array to include all `ALL_PERMISSION_KEYS`.

### 1. Admin Invoice List Fix — `ListResponse` Bug

**Root cause:** `admin/src/api/invoices.api.ts` typed the response as `{ data: ListResponse<AdminInvoice> }` but the backend `sendList` returns `{ success, data: T[], meta: { page, limit, total, totalPages } }`. At runtime `r.data.data` was `AdminInvoice[]`, so the page's `data?.data ?? []` returned `[]` and `data?.total` returned `undefined`.

**Fix:**
- `admin/src/api/invoices.api.ts` — `list()` now returns `r.data` (the full object) typed as `InvoiceListResult { data: AdminInvoice[], meta: {...} }`
- `admin/src/app/(dashboard)/invoices/page.tsx` — `data?.total` → `data?.meta?.total`, added `data?.meta?.totalPages`

**Note:** Same `ListResponse` bug still exists in orders, prescriptions, compounding, and other admin list pages — documented in remaining work below.
