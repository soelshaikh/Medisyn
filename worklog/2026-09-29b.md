## Files Modified

### Backend
- `backend/src/modules/orders/orders.service.ts`
  - **Bug 1 (P0)**: `cancelMyOrder` — added `const prevStatus = order.status` before mutation; `_orderStatusSideEffects` now receives the correct pre-cancel status instead of `"cancelled"` as both `fromStatus` and `toStatus`
  - **Bug 2 (P1)**: `checkout` — changed `EmailTriggerService.fire("orders", null, "confirmed", ...)` → `fire("orders", null, "pending", ...)` with matching `status: "pending"` in context
- `backend/src/modules/email/email-trigger.service.ts`
  - **Bug 3 (P1)**: Rewrote `resolve()` from non-deterministic `$or [fromStatus, null, "*"]` single query to a two-query priority approach: exact `fromStatus` match first; wildcard fallback (`null`/`"*"`) only when no exact match exists and `fromStatus !== null`
- `backend/src/modules/ask-pharmacist/ask-pharmacist.service.ts`
  - **Bug 4a (P1)**: Replaced `EmailService.sendAskPharmacistRespondedEmail(...)` with `EmailTriggerService.fire("ask-pharmacist", "open", "answered", { customer, refId, extra: { questionSubject, responseText } })`
  - Changed import: `EmailService` → `EmailTriggerService`
- `backend/src/modules/appointments/appointments.service.ts`
  - **Bug 4b (P1)**: Replaced `EmailService.sendAppointmentStatusChangedEmail(...)` with `EmailTriggerService.fire("appointments", oldStatus, status, { customer, refId, extra: { service, dateTime } })`
  - Added `oldStatus: AppointmentStatus` parameter to `_appointmentStatusSideEffects`; updated the call site on the `updateBookingStatus` side-effects line to pass `oldStatus`
  - Changed import: `EmailService` → `EmailTriggerService`
- `backend/src/database/seed.ts`
  - Updated orders email trigger seed: `{ fromStatus: null, toStatus: "confirmed" }` → `{ fromStatus: null, toStatus: "pending", description: "Order placed — acknowledgement to customer" }` — aligns with the corrected checkout fire call

### Admin UI
- `admin/src/app/(dashboard)/prescriptions/[id]/page.tsx`
  - **P1 Prescription UI fix**: Replaced broken `const RX_STATUSES = ["active", "expired", "cancelled"]` (old schema) with `RX_TRANSITIONS` map defining valid forward-only transitions with required permission per move
  - Added `useAdminAuthStore` import; `hasPermission` used to filter which next states are shown
  - "Update Status" button disabled when no transitions are available to current user
  - Modal Select `options` now derived from `availableTransitions` — only reachable + permitted next states shown; opens pre-selected to the first available transition
- `admin/src/app/(dashboard)/compounding/[id]/page.tsx`
  - **P3 Compounding UI fix**: Same pattern — replaced `COMPOUNDING_STATUSES` flat array with `COMPOUNDING_TRANSITIONS` map covering all 6 live states
  - Added `useAdminAuthStore` / `hasPermission`; status modal only shows states the current actor can reach based on permissions
  - "Update Status" button disabled at terminal states (`delivered`, `cancelled`) and when actor lacks all transition permissions
