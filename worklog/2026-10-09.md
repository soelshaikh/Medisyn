## Bugs Found and Fixed

1. **Circular dependency: `auth.router` → `app.ts` → `auth.router`**
   - `auth.router.ts` imported `authMiddleware` from `@/app`; `app.ts` imported `authRouter` from `./core/auth/auth.router`
   - Node.js module cache resolves circular deps by returning an incomplete module — `authMiddleware` was `undefined` at call time
   - Fix: extracted to `auth.middleware.ts`, broke the cycle

2. **dotenv not loaded when tests import `createApp()` directly**
   - `src/index.ts` (server entry) calls `dotenv.config()` before importing `app.ts`, but tests import `app.ts` directly
   - When `src/db/index.ts` is evaluated, `process.env.DATABASE_URL` was undefined → postgres connected with OS username → auth failed
   - Fix: `dotenv.config()` added to `src/db/index.ts` + `vitest.config.ts` `setupFiles`

3. **`app_super_admin_login` lacked BYPASSRLS — RLS blocked superAdminDb queries**
   - `create-roles.sql` granted `app_super_admin` (BYPASSRLS) to `app_super_admin_login` via `GRANT`, expecting BYPASSRLS to be inherited
   - PostgreSQL does not inherit role attributes through membership — confirmed via `SELECT rolbypassrls FROM pg_roles`
   - `getFacilityUserByUserAndFacility`, `createSession`, `writeAuthAuditEntry` all used `superAdminDb` and were blocked by RLS on facility-scoped tables
   - Fix: `ALTER ROLE app_super_admin_login BYPASSRLS;` on the live DB + updated `create-roles.sql`
