## Decisions (CONFIRMED)

- Subject files use `.txt` extension (not `.hbs`) — subjects are plain strings, Handlebars-compiled but no HTML needed. Bodies use `.hbs`.
- `notifications.service.ts` uses `workerDb` (BYPASSRLS) for all notification reads/writes rather than `withTenantContext`, because:
  - Broadcast fan-out is cross-user (no single facility session)
  - Prune cron has no facility context
  - `createNotification()` receives a `TenantTransaction` from the caller's own `withTenantContext`, so RLS is already set for the primary operation
- `GET /auth/me` added fresh to auth.router.ts (no existing /me route existed)
- Appointment-reminder scan uses `workerDb.execute(sql\`...\`)` with raw SQL JOIN across 4 tables — no per-facility RLS needed since worker has BYPASSRLS
