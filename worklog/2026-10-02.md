## Changes

### 1. Admin Orders List — Customer Column Showing "—" (FIXED)

**Bug:** The CUSTOMER column in `/admin/orders` showed "—" for all logged-in user orders. Only guest orders showed a name because the code read `o.guestInfo?.fullName`, but for registered users `guestInfo` is `null` and `userId` was returned as a raw ObjectId string (not populated).

**Fix:**
- `backend/src/modules/orders/orders.service.ts` (`listAdminOrders`, line ~188): Added `.populate("userId", "email fullName phone")` to the list query — same as `getOrder` already did.
- `admin/src/app/(dashboard)/orders/page.tsx`: Customer column now resolves name/email from `guestInfo` first, then falls back to the populated `userId` object. ORDER sub-label (email) has the same fix.

**Decision:** CONFIRMED fix — no behavior change, pure data display bug.

### 2. Patient Order Messaging — "Messages from Pharmacy" Section (NEW)

**Context:** Admin order detail has a "Patient Thread" UI where admin can send messages to patients. The patient had no way to see or reply to these messages — the backend route existed (`GET /threads/order/:orderId/patient/messages`) but no frontend used it, and there was no patient POST endpoint.

**Backend added:**
- `backend/src/modules/threads/thread.routes.ts`: New route `POST /threads/:entityType/:entityId/patient/messages` — allows authenticated patients to reply to any entity thread (order, prescription, etc.). Uses the existing `postMessage` service with `role: "patient"`.

**Frontend API added:**
- `frontend/src/api/threads.api.ts`: Added `getEntityMessages(entityType, entityId, opts?)` and `postEntityMessage(entityType, entityId, payload)` to `patientThreadsApi`.

**Patient UI added:**
- `frontend/src/app/patient/orders/[id]/page.tsx`: New "Messages from Pharmacy" section at the bottom of the order detail page:
  - Fetches thread via `useQuery` with 30s refetch interval (auto-polls for new messages)
  - Auto-scrolls to latest message on new message arrival (`useEffect` + `ref`)
  - Chat bubble layout: admin messages left-aligned (slate background), patient messages right-aligned (brand blue)
  - Textarea reply box with Ctrl+Enter keyboard shortcut + Send button
  - Empty state: helpful prompt when no messages exist
  - Message count badge in section header

**Decision:** CONFIRMED — patient can now both read and reply to order-specific pharmacy messages.
