## Architecture Notes

### order.service.ts — placeOrder transaction order

```
1. verifyPreviewToken (JWT verify, claims.sub + claims.facilityId match)
2. findCartByUserId → CART_EMPTY if null
3. findCartItemsFull → CART_EMPTY if empty
4. findMethodById → SHIPPING_METHOD_NOT_FOUND if inactive
5. ensureSequenceRow (INSERT ... ON CONFLICT DO NOTHING)
6. lockAndGetSequence (SELECT FOR UPDATE — serialize concurrent orders)
7. For each item: lockInventoryRecord SELECT FOR UPDATE → collect outOfStockItems → INSUFFICIENT_STOCK if any
8. Re-compute totals from scratch (subtotal, tax via calculateTax, shippingCost, total)
9. formatOrderNumber from locked sequence value
10. insertOrder
11. insertOrderItem (x items)
12. insertOrderStatusHistory (pending, changedById=null)
13. For each item: updateInventoryQuantity (qty-) + insertInventoryTransaction (SALE)
14. incrementSequence
15. deleteAllCartItems + deleteCart
16. createAuditEntry (order.placed)
17. Return PlaceOrderResult with estimated delivery dates
```

### Commerce module structure

```
/api/v1
  /cart              ← cartRouter (GET, POST /items, PATCH /items/:id, DELETE /items/:id, DELETE /, POST /merge)
  /shipping-methods  ← shippingMethodRouter (public GET; admin CRUD)
  /checkout          ← checkoutRouter (POST /preview, POST /place)
  /orders            ← orderRouter (patient: GET, GET /:id, POST /:id/cancel; admin: full CRUD)
```
