### 1. Input type="number" → type="text" with numeric guard

**Problem:** All numeric inputs across the admin used `type="number"` showing browser spinners.  
**Fix applied to:**
- `admin/src/app/(dashboard)/invoices/new/page.tsx` — all 5 numeric fields (qty, unit price, tax amount, tax rate, discount)
- `admin/src/app/(dashboard)/orders/[id]/page.tsx` — allocated qty input

**How:** Replaced `type="number"` with `type="text" inputMode="decimal|numeric"` + shared `blockNonNumeric(e, allowDot)` handler that intercepts `onKeyDown`. Allows: digits, backspace/delete, arrow/home/end, Ctrl+A/C/V/X, and a single `.` for decimal fields.

### 3. UHID (Unique Health ID) system

#### Backend

**`backend/src/lib/counter.ts`** *(new)*
- MongoDB Counter collection with atomic `findOneAndUpdate + $inc`
- `nextUHID()` returns `MED-000001` format (zero-padded 6 digits)

**`backend/src/modules/users/users.schema.ts`**
- Added `uhid?: string` to `IUser` interface
- Added `uhid: { type: String, unique: true, sparse: true }` to schema (sparse = existing users without UHID don't conflict)

**`backend/src/modules/auth/auth.service.ts`**
- Imported `nextUHID` from `@/lib/counter`
- Calls `nextUHID()` before `UserModel.create()` in `register()` — every new patient gets a UHID at registration

**`backend/src/modules/users/users.routes.ts`**
- Added `GET /users/search?q=...` endpoint (placed before `/:id` to avoid route conflict)
- Searches: `fullName`, `email`, `phone`, `uhid` (prefix match) — all case-insensitive regex
- Returns top 10: `{ _id, uhid, fullName, email, phone }`
- Requires `users.read` permission
- Also added `uhid` to the list response (`GET /`)

**Decision:** No backfill — only new users get UHIDs. CONFIRMED by user.

**`admin/src/api/users.api.ts`**

**`admin/src/app/(dashboard)/invoices/new/page.tsx`**
