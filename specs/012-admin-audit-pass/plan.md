# Implementation Plan: Admin Panel Audit Pass

**Branch**: `012-admin-audit-pass` | **Date**: 2026-10-11 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/012-admin-audit-pass/spec.md`

---

## Summary

The admin panel (`admin/`) has ~80+ pre-built pages and 24 API modules. TypeScript is clean. However, the majority of pages will fail at runtime due to three classes of bugs: (1) wrong backend API paths, (2) incorrect response shape extraction, and (3) a fundamental `_id` vs `id` type mismatch — the admin types were written for MongoDB but the backend uses PostgreSQL (Drizzle), which returns `id: string` UUIDs, not `_id`. Additionally, ~10 admin modules call routes that simply do not exist on the backend. This plan fixes all known integration issues and creates the four most critical missing backend route modules.

## Implementation Groups

### Group A: Type System Fix (`_id` → `id`)

**Files**: `admin/src/types/admin.ts`

All TypeScript interfaces rename `_id: string` → `id: string`. The change propagates naturally through TypeScript — the compiler will highlight every usage of `._id` in pages and API modules, making it easy to find all call sites. This is the highest-priority fix because it affects every page.

**Affected interfaces**: AdminUser, AdminRole, AuditLog, AdminOrder, AdminBrand, AdminProduct, AdminCoupon, AdminPrescription, AdminCompoundingRequest, AdminAskPharmacist, VaccineService, AppointmentSlot, AppointmentBooking, AdminAilmentRequest, AdminInvoice, InvoiceLineItem, InvoiceLineItemHistory, PaymentTransaction, PaymentAllocation, FAQ.

**After fix**: Run `tsc --noEmit`. Errors will point to every page/component using `._id`. Fix each by changing `.id`. This ensures no page navigates to `/path/undefined`.

### Group B: API Path + Shape Fixes (admin frontend)

**Files**: `admin/src/api/*.ts`

Fix each API module to call the correct backend path and extract the correct response keys:

1. **`dashboard.api.ts`**: Change `GET /admin/dashboard/metrics` → `GET /admin/reports/dashboard`. Extract from `r.data.data` (same as reports pattern).

2. **`orders.api.ts`**: 
   - `ordersApi.list()`: `GET /orders/admin` → `GET /admin/orders`; extract `rows` from `r.data.data` (array), `total` from `r.data.pagination.total`
   - `ordersApi.getById()`: `GET /orders/admin/:id` → `GET /admin/orders/:id`
   - `ordersApi.updateStatus()`: `PATCH /orders/admin/:id/status` with body `{status}` → `PATCH /admin/orders/:id/status` with body `{newStatus}`
   - `ordersApi.addNote()`: `POST /orders/admin/:id/notes` → `PATCH /admin/orders/:id/notes`

3. **`notifications.api.ts`**:
   - `list()`: extract from `r.data.data.items` (not `r.data.data.data`), total from `r.data.data.pagination.total`
   - Remove `unreadCount()` method (endpoint doesn't exist; unread count is in the list response)

4. **`reports.api.ts`**:
   - `customers()` → change path from `/admin/reports/customers` to `/admin/reports/patients`

5. **`products.api.ts`**:
   - Change `BASE = "/products"` → `BASE = "/catalogue/products"`; verify all paths against full product router

### Group C: New Backend Routes (super-admin module)

**Files**: new files under `backend/src/core/super-admin/`

All new routes require `isSuperAdmin === true` on the JWT. Create a `requireSuperAdmin` middleware:

```typescript
function requireSuperAdmin(req: Request, res: Response, next: NextFunction) {
  if (!req.auth?.isSuperAdmin) {
    return next(new AppError('FORBIDDEN', 'Super admin access required', 403));
  }
  next();
}
```

**Route: GET `/admin/users`** (list facility users)
- Query `superAdminDb` to join `facility_users` + `users` + `facility_roles`
- Params: `page`, `limit`, `search` (email/name), `facilityId` (optional filter)
- Returns: `{ data: UserListItem[], pagination: { page, limit, total, totalPages } }`
- `UserListItem`: `{ id, email, firstName, lastName, roles: [{ id, name }], isActive, joinedAt }`

**Route: GET `/admin/users/:id`** (user detail)
- Returns full user + all facility memberships + assigned role name

**Route: PATCH `/admin/users/:id/status`** (activate/deactivate)
- Body: `{ isActive: boolean }`
- Updates `facility_users.is_active`

**Route: PATCH `/admin/users/:id/roles`** (assign role)
- Body: `{ roleId: string, facilityId: string }`
- Updates `facility_users.role_id`

**Route: GET `/admin/roles`** (list facility roles)
- Query `superAdminDb` for `facility_roles` with permission count
- Returns: `{ data: RoleListItem[] }` where `RoleListItem: { id, facilityId, name, isSystemRole, permissionCount, createdAt }`

**Route: POST `/admin/roles`** (create role)
- Body: `{ facilityId: string, name: string }`
- Validates name uniqueness per facility
- Returns: `{ data: FacilityRole }`

**Route: PATCH `/admin/roles/:id`** (update role name)
- Body: `{ name?: string }`
- Cannot modify system roles
- Returns: `{ data: FacilityRole }`

**Route: DELETE `/admin/roles/:id`** (delete role)
- Cannot delete system roles or roles with assigned users
- Returns 200 on success

**Route: PUT `/admin/roles/:id/permissions`** (set role permissions)
- Body: `{ permissions: string[] }` (array of permission keys e.g. `["orders.read", "prescriptions.write"]`)
- Replaces all permissions for the role (delete all + insert new)
- Returns: `{ data: FacilityRole & { permissions: string[] } }`

**Route: GET `/admin/permissions`** (list all permissions)
- Query `superAdminDb` for all rows in `permissions` table
- Returns: `{ data: Array<{ key: string; name: string; description: string | null }> }`
- Groups by domain prefix (e.g. `orders.*`, `prescriptions.*`, `healthcare.*`) in the response

**Route: GET `/admin/audit`** (paginated audit log)
- Query `superAdminDb` for `audit_log` rows ordered by `created_at DESC`
- Params: `page`, `limit`, `facilityId`, `action`, `actorId`, `dateFrom`, `dateTo`
- Returns: `{ data: AuditEntry[], pagination: { page, limit, total, totalPages } }`
- `AuditEntry`: `{ id, facilityId, actorId, actorType, action, resourceType, resourceId, metadata, ipAddress, createdAt }`
